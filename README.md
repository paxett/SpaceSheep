# SpaceSheep

Unity-проект (Unity 6000.5.6f1, URP 2D, Input System). Основная сцена — `Assets/Scenes/SampleScene.unity`.

Помимо геймплея за овцу в проекте есть мини-игра «Ремонт корабля»: игрок диагностирует и устраняет поломки корабля в доке. Все данные этой мини-игры описываются одним ассетом — `RepairSessionData`.

# Структура ассета `RepairSessionData`

- **Файл данных:** `Assets/Resources/RepairSessionData.asset`
- **Модель данных:** `Assets/Scripts/Repair/RepairSessionData.cs` (ScriptableObject, классы `RepairFault`, `RepairBreakdown`, `RepairDiagnostic`)
- **Загрузка в рантайме:** `Resources.Load<RepairSessionData>("RepairSessionData")` в `Assets/Scripts/Repair/RepairBootstrap.cs`

Ассет состоит из двух блоков: **палитры цветов** (4 цвета) и **контента сессии** (массивы неисправностей, поломок и диагностик). Связи между сущностями задаются текстовыми ID. Редактируется ассет в Inspector в Unity; новый такой ассет создаётся через меню **Assets → Create → Space Sheep → Repair Session Data**. Правка кода для изменения данных не нужна.

## Палитра цветов

Поля `color1`…`color4` задают цвета всех графических элементов мини-игры. UI строится процедурно (заливки `Image`/`SpriteRenderer`, обводки), поэтому палитра полностью определяет цветовую схему.

| Поле | Значение по умолчанию | Назначение |
|------|-----------------------|------------|
| `color1` | `#00cfff` — голубой (0, 0.81, 1) | **Активация / подтверждение.** Плитка выбранной неисправности; овалы поломок на корабле; кнопка «Запустить диагностику»; плитки неисправностей и овалы чинимых поломок во время выполнения диагностики. |
| `color2` | `#ff9f1c` — оранжевый (1, 0.62, 0.11) | **Связь / кандидат.** Неисправности-последствия выбранной поломки; диагностики-кандидаты, способные выявить поломку; овалы поломок, которые устранит выбранная диагностика. |
| `color3` | `#7cff6b` — зелёный (0.49, 1, 0.42) | **Выбор / обводка.** Обводка выбранной поломки и выбранной диагностики (плитки и овалы на корабле). |
| `color4` | `#ffd424` — жёлтый (1, 0.83, 0.14) | **Прогресс и символ диагностики.** Прогресс-бар выполнения диагностики; ромб-символ диагностики на корабле. |

> Служебные цвета (тёмные панели, белый текст, красный таймер при остатке ≤ 10 сек, зелёный/красный акценты окон победы/поражения) в палитру не входят и заданы в коде `Assets/Scripts/Repair/RepairWindowController.cs`.

## Контент сессии

### Неисправности — `faults`

Массив объектов `RepairFault` — это условия, с которыми игрок начинает шаг 1 (панель слева).

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор, например `Н1`. |
| `displayName` | `string` | Название на панели неисправностей. |
| `breakdownIds` | `string[]` | ID поломок, возможных при этой неисправности (овалы на корабле в шаге 1). |

### Поломки — `breakdowns`

Массив объектов `RepairBreakdown` — овалы на спрайте корабля, которые игрок выбирает на корабле.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор, например `П1`. |
| `displayName` | `string` | Метка на овале корабля. |
| `shipPosition` | `Vector2` | Позиция овала на спрайте корабля в нормализованных координатах 0..1 (0,0 — низ-лево, 1,1 — верх-право). |
| `ovalSize` | `Vector2` | Размер овала в нормализованных единицах относительно размера корабля. |
| `consequenceFaultIds` | `string[]` | ID двух неисправностей, которые влечёт эта поломка (подсвечиваются цветом 2 на панели неисправностей). |
| `diagnosticIds` | `string[]` | ID диагностик, способных выявить эту поломку; после выбора поломки активны только они. |

### Диагностики — `diagnostics`

Массив объектов `RepairDiagnostic` — панель справа; одна из них запускается игроком для ремонта.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор, например `Д1`. |
| `displayName` | `string` | Название на панели диагностики. |
| `durationInMinutes` | `float` | Длительность диагностики в минутах (ЧЧ:ММ) — показывается на плитке. |
| `durationSeconds` | `float` | Фактическое время заполнения прогресс-бара в реальных секундах. |
| `breakdownIds` | `string[]` | ID поломок, которые находит и устраняет эта диагностика по завершении. |

## Связи между сущностями

Связи двунаправленны и задаются через ID, поэтому при редактировании они должны быть согласованы вручную:

- `RepairFault.breakdownIds` ↔ `RepairBreakdown.consequenceFaultIds` (неисправность ↔ поломки);
- `RepairDiagnostic.breakdownIds` ↔ `RepairBreakdown.diagnosticIds` (поломка ↔ диагностики).
